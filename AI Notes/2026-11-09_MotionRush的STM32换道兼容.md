# Motion Rush 的 STM32 换道兼容

用户在确认先试玩的安排后要求继续实施。基于同步后的 `5903be9`，修复 PC 接口并准备实物试玩。

## 改动

- `runner.py` 的 `set_motion_state()` 统一接收共享控制器输出的 [-1, 1] 归一化 Roll。左右换道阈值改为 ±0.30，回中阈值 ±0.10，中间区间保持目标赛道。
- 默认死区 4°、满量程 25° 下，约相当于校准姿态左右倾斜 10.3° 换道、回到 6.1° 内回中，接近队友原先 10°/6° 的设计。没有通过绕开校准、直接使用原始角度解决问题。
- 跑酷开始、暂停/恢复等状态转换清除未完成的手势，菜单/暂停动作不会积压到实际跑步。
- STM32 模式运行中数据失效时，跑酷同高尔夫一样暂停并打开控制面板；重连、F4 校准后 Start / Resume，可切 F3 键盘继续。
- 失焦时跑酷保持暂停；设置面板不能在失焦时恢复运行。
- 跑酷菜单提示和 README 更新为实际 STM32 / F3 / F4 / F5 用法。下滑仍为 S / Down；键盘换道请用 F3 切 Keyboard，否则 STM32 每帧会按姿态设定赛道。
- 诊断启动器新增 runner_status、runner_lane、runner_mode、runner_height，方便试玩后确认是否收到事件和实际起跳。
- 没有修改固件、共享上提判定、玩家保存的力度、跑酷障碍/碰撞/评分/速度或高尔夫地图物理。

## 验证

`.venv/Scripts/python.exe -X utf8 -m unittest discover -s MotionGolf_Stage2_v3/tests -v`：14 项通过。

新增四项通过实际主循环和模拟设备时间/六轴数据验证：

1. 校准后左倾、右倾、回中、缓冲区保持和上提实际起跳。
2. 串口断流后暂停，距离冻结，切键盘后恢复、换道及下滑。
3. 菜单与失焦时的上提不误跳，重新聚焦仍暂停，手动恢复后新上提能起跳。
4. 传感器错误后 Retry、重新校准、恢复和起跳。

原有十项高尔夫集成测试均通过。实物跑酷手感仍待用户试玩；模拟测试并不证明先前硬件 I²C 间歇问题已经解决。

本轮保存为一个本地提交，不推送云端。重新打开游戏后选择 Motion Rush，F4 自然握持校准，Start Run，测试左右倾斜、回中和上提，S / Down 下滑。
