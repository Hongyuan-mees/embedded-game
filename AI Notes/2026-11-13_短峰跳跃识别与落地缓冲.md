# 短峰跳跃识别与落地缓冲

用户授权落实上一轮逐层分析的相应修改。基于 `54dfcfa`，保留本机 0.28g、源默认 0.30g，不通过降低玩家力度替代修复。

## 识别层

- 保留连续40ms越过力度的原分支，新增支持短峰的分支。
- 检查最近80ms的连续支撑样本；低于力度一半时清除支撑。峰值需达到玩家力度，至少两个样本同时达到力度的一半和峰值的三分之一，总正向作用量达到力度乘40ms。
- 第三分之一的相对支撑约束用于避免异常巨大峰借一个很小的尾部触发；历史夹具中饱和样本附近的异常峰仍不被新增分支接受。
- 单帧贡献最多20ms，不能靠一个间隔较长的迟到样本满足持续时间。
- 候选结束、下压短抑制、成功事件、数据/场景重置会清除支撑窗口；不跨隔开的尖峰、暂停或断流拼接动作。
- 新增 `event_reason` 诊断字段，区分 sustained / supported_short_peak。原有漂移恢复、700ms冷却、下压短抑制及无严格逐次静止要求保留。

## 角色层

- `RunnerGame.request_jump()` 返回实际成功与否，供明确记录事件到动作结果。
- 若体感跳跃事件恰在角色不可操作的时刻，最多缓冲0.20秒；这段时间内落地/动作锁结束即执行一次，过期失效。过渡重置清除缓冲，不跨暂停、失焦、断线、校准和模式切换补跳。
- 缓冲起跳优先处理并清除待下滑。保持原跳跃速度/重力、下滑动作时长及不能空中二段跳的规则；不承诺长时间下滑中可即时起跳。
- 键盘按键沿用原即时请求，不自动重复排队。
- 新增实际 `runner_jump_request` 诊断事件，记录 accepted、拒绝原因、前后状态、角色动作锁和缓冲剩余时间，避免仅凭 detector event 宣称实际已经起跳。

## 验证与边界

- Stage 1共享控制测试90项通过，Stage 2集成测试26项通过，合计116项。
- 原历史有标签夹具的预期事件和原策略事件列表均未修改，测试仍通过；孤立尖峰、分隔尖峰、巨峰加微弱尾部、作用量不足、下压抑制、侧向分量及冷却等负/正例继续验证。
- 保存本次65.35–65.85秒、66.9–67.35秒实测片段及参考状态为 `MotionGolf_Stage1_v4/tests/fixtures/supported_short_pulses_20261113.json`。旧算法均0事件，新规则每段1事件。这是规则接受的原未触发候选，原始记录没有逐次人的动作意图标注，不能把它直接称为测得成功率。
- 初次完整纯检测器回放18→23事件，有1个旧事件未在150ms内匹配：新短峰约55.293秒先进入冷却，旧事件55.571秒被覆盖。这个发现促使本轮补上角色输入缓冲，而非只报告识别事件变多。
- `diagnostics/validate_short_pulses_20261113.py` 对同一11710样本做检测器与角色输入链路比较：原15次实际起跳，新18次；原起跳均在新结果350ms内有匹配，新增3次符合新规则。约55秒事件在新链路先缓冲后于55.374秒起跳，没有在落地附近直接吞掉。
- 该回放使用原录制的UI/就绪状态、固定20ms角色更新，禁用随机障碍碰撞以单独比较输入链路，不是全游戏模拟或新的实物成功率测试；新增事件的真实意图仍需玩家试玩确认。
- 报告 `diagnostics/short_pulse_validation_20261113.json`、`diagnostics/short_pulse_runner_replay_20261113.json` 保留比较证据。完整原始活动日志只在本机；短夹具足以独立执行单元测试。
- 全部日志脚本语法检查和 git diff --check 通过。
