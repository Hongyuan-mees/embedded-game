# STM32 Motion Controller

基于 STM32F103C8T6、六轴传感器、XY 摇杆、旋转编码器和独立按键的游戏控制器。
固件通过 USB CDC 虚拟串口以约 50 Hz 输出姿态、动作与各输入模块的状态。
当前验收版本更新于 2026-11-14。

组员首次使用、工程导入、烧录和游戏端解析方法请参阅
[`PROJECT_GUIDE.md`](PROJECT_GUIDE.md)。

## 工程和固件下载

- 下载完整仓库后，在 CubeIDE 中导入包含 `.project` 的 `motion-controller` 目录。
- 独立工程包位于 [`releases/motion_controller_project.zip`](releases/motion_controller_project.zip)。
- 已烧录验收的固件位于 [`releases/motion_controller.elf`](releases/motion_controller.elf)。
- `Core/` 包含应用代码，`Drivers/` 和 `Middlewares/` 包含构建依赖。
- `.ioc` 与当前手工集成代码尚未完全同步，修改外设配置后需要逐项合并生成结果。

## 已验证状态

- ST-LINK 下载、校验和复位正常。
- Windows 可识别为 `USB Serial Device (COM7)`（COM 号可能随电脑变化）。
- I2C1 使用重映射引脚：`PB8=SCL`、`PB9=SDA`。
- 传感器在地址 `0x68` 应答，本模块 `WHO_AM_I=0x74`。固件允许 `0x68` 和
  `0x74` 通过身份检查，本次实测结果仅适用于当前模块，具体芯片型号尚未确认。
- 平放、约 35 度倾斜、跳跃动作和静止防误触均已实测通过。
- 编码器双向计数、按下和松开已实测。
- 摇杆四向端点、回中和按压已实测。
- 独立按键松开、按住、再次松开已实测。

## 当前实物接线

2026-11-14 核心板移动后，用户确认 VBT 位于 H40，另一排的 3.3V 位于 D40，
摇杆 VRx 接 J44、VRy 接 J45。以下其余坐标按原核心板排针顺序推算，仍需对照
板上丝印核对。D 列与 A～E 同排连通，H 列与 F～J 同排连通。

| 接线用途 | STM32 引脚 | 新位置 | 同排可用接线孔 |
|---|---|---|---|
| 摇杆 VRx（已确认 J44） | PA0 | H44 | J44 |
| 摇杆 VRy（已确认 J45） | PA1 | H45 | J45 |
| 摇杆 SW（PA2 按压读取已验证） | PA2 | H46 | J46 |
| 编码器 CLK | PB6 | D46 | A46 或 E46 |
| 编码器 DT | PB7 | D45 | A45 或 E45 |
| 编码器 SW | PB12 | D59 | A59 或 E59 |
| 独立按键 S（按下、松开读取已验证） | PB13 | D58 | A58 或 E58 |
| MPU SCL | PB8 | D44 | A44 或 E44 |
| MPU SDA | PB9 | D43 | A43 或 E43 |
| MPU VCC | 5V | D42 | A42 或 E42 |
| 公共地与核心板连接 | GND | D41 | A41 或 E41 |
| 摇杆、编码器供电 | 3.3V | D40 | A40 或 E40 |

STM32 GND、MPU GND、MPU AD0 和新增模块 GND 使用同一个公共地。
公共地具体孔位尚未记录。MPU `XDA`、`XCL`、`INT` 悬空，AD0 接地后地址为
`0x68`。摇杆标注 `+5V` 的供电脚按本项目方案接 3.3V。

## USB 串口协议

波特率可设为 `115200`（USB CDC 实际传输不依赖 UART 波特率）。每行一个数据包。

```text
ROLL:-12.3,PITCH:4.5,JUMP:0,ENC:0,ENC_SW:0,JOY_X:2048,JOY_Y:2048,JOY_SW:0,JOY_OK:1,KEY:0
```

- `ROLL`：横滚角，单位为度。
- `PITCH`：俯仰角，单位为度。
- `JUMP`：平时为 `0`；检测到跳跃动作后约 300 ms 内为 `1`。
- `ENC` 表示编码器累计正交边沿计数，上电或复位后从 0 开始。方向符号和每个
  机械卡点对应的计数需要实测确认。
- `ENC_SW` 表示编码器按压状态，按下为 `1`，松开为 `0`，采用 25 ms 消抖。
- `JOY_X`、`JOY_Y` 是 PA0、PA1 的 12 位 ADC 原始值，范围 0～4095，摇杆
  回中时通常接近 2048，实际中心和端点需要实测。
- `JOY_SW` 使用 PA2，按下为 `1`，松开为 `0`，采用 25 ms 消抖。
- `JOY_OK` 为 `1` 表示本轮两路 ADC 转换成功。为 `0` 时接收端应忽略 X/Y，
  输出值可能是之前的读数。此字段仅表示 ADC 采样成功。
- `KEY` 使用 PB13 上拉输入和 25 ms 消抖，按下为 `1`，松开为 `0`。
  按键模块 S 接 PB13，负极接公共地，中间针留空。游戏端对单次动作可检测
  `KEY` 从 `0` 到 `1` 的变化。
- MPU 正常时数据行约 50 Hz，MPU 出错时切换到错误状态行和低频重试。

游戏端应按换行符读取，再按逗号和冒号解析字段，允许新增字段。不要写死 `COM7`，应允许
用户选择 Windows 当前分配的 COM 口。

`JUMP` 的高电平保持约 300 ms，`ENC_SW`、`JOY_SW`、`KEY` 按住时持续为 `1`。
游戏中的单次跳跃或确认操作应按 `0 -> 1` 上升沿触发。`ENC` 使用相邻包的差值
表示旋转输入，设备重启后累计计数重新从 0 开始，接收端应重建基准。

编码器本轮接入使用 CLK -> PB6、DT -> PB7、SW -> PB12、+ -> 3.3V、GND ->
公共地。TIM4 使用编码器模式计数。编码器字段也附加在 MPU 状态和错误行末尾，
这些行仍应按状态行处理。本轮编码器固件已编译、烧录并校验。实测旋转后计数为
`9`，反转后减至 `3`，停住后保持稳定，按下为 `ENC_SW:1`，松开为 `0`。
同次测试中 MPU 姿态数据正常输出。每个机械卡点对应的计数仍待标定。

摇杆版本已于 2026-11-14 编译、烧录并校验成功，完成四向端点、回中和按压读取。
用户确认 VRx -> PA0/J44、VRy -> PA1/J45，PA2 按压信号实测有效。

| 当前安装方向下的操作 | JOY_X 约值 | JOY_Y 约值 |
|---|---|---|
| 松开回中 | 2060 | 2024 |
| 左推到底 | 2060 | 4091 |
| 右推到底 | 2060 | 2 |
| 前推到底 | 2 | 2032 |
| 后推到底 | 4091 | 1402 |

后推测试同时带有 Y 轴偏移，随后回中按压时 X/Y 恢复到约 2059/2024。
按住时 `JOY_SW=1`，此前松开时为 `0`。全部摇杆采集窗口内 `JOY_OK=1`。
游戏端应按实测安装方向映射左右与前后，并以实测中心值计算偏移。

独立按键版本已于 2026-11-14 编译、烧录并校验成功。分别采集约 4 秒数据，
松开时 `KEY=0`，按住时 `KEY=1`，再次松开后恢复 `KEY=0`。三个窗口分别
收到 201 组完整数据，MPU 姿态行持续输出，`JOY_OK` 持续为 `1`。

## 供电与烧录

不要同时用 ST-LINK 3.3 V 和 Type-C 给核心板供电。

- 烧录：先拔 Type-C，再按原接线接通 ST-LINK，烧录
  `Debug/motion_controller.elf`。
- 运行：拔掉 ST-LINK USB，再接 Type-C；MPU6050 由核心板 5V 引脚供电。
- `BOOT0` 保持为 0。

不要在 STM32CubeMX 中直接执行 `Generate Code`，除非已经备份当前 USB CDC 和
I2C 修改；未同步的重新生成可能覆盖现有代码。
